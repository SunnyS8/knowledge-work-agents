# Сквозные рабочие процессы

Готовые шаблоны для задач, затрагивающих несколько доменов. Каждый процесс: цель → шаги (скилл → артефакт) → финальный результат. Артефакт каждого шага передаётся как вход следующему.

---

## 1. Запуск продукта (полный GTM-процесс)

**Цель:** вывести продукт/фичу от идеи до запуска и пост-запускного анализа согласованно во всех функциях.

**Фаза 1. Идея и валидация**

| Шаг | Скилл | Артефакт |
|---|---|---|
| 1. Брейншторм идеи | product-management: product-brainstorming | Идеи, приоритизация |
| 2. Синтез исследований рынка/пользователей | product-management: synthesize-research | Инсайты, обоснование |
| 3. Конкурентный брифинг | product-management: competitive-brief | SWOT, позиционирование |
| 4. Спека продукта | product-management: write-spec | Спека |
| 5. Метрики успеха | product-management: metrics-review | KPI запуска |

**Фаза 2. Планирование**

| Шаг | Скилл | Артефакт |
|---|---|---|
| 6. Роадмап и план релиза | product-management: roadmap-update | План релиза, даты |
| 7. Прогноз выручки | sales: forecast | Прогноз, план продаж |
| 8. Спринт-планирование | product-management: sprint-planning | План итераций |

**Фаза 3. Готовность к запуску**

| Шаг | Скилл | Артефакт |
|---|---|---|
| 9. План кампании | marketing: campaign-plan | План кампании и каналов |
| 10. Контент и материалы | marketing: content-creation | Посты, письма, лендинг |
| 11. Email-последовательность | marketing: email-sequence | Цепочка писем |
| 12. SEO-план | marketing: seo-audit | SEO-план/аудит |
| 13. Подготовка продаж | sales: call-prep / draft-outreach | Скрипты звонков, аутрич |
| 14. Статьи базы знаний | customer-support: kb-article | Статьи KB к релизу |
| 15. Юридическая проверка материалов | legal: compliance-check | Одобрение, правки |

**Фаза 4. Запуск и пост-запуск**

| Шаг | Скилл | Артефакт |
|---|---|---|
| 16. Апдейт стейкхолдерам | product-management: stakeholder-update | Статус, коммуникация |
| 17. Отчёт по кампании | marketing: performance-report | Результаты кампании |
| 18. Анализ метрик продукта | product-management: metrics-review | Пост-запускный анализ |
| 19. Разбор эскалаций | customer-support: customer-escalation | Резолв проблем поддержки |

**Финальный результат:** пакет запуска — спека, план релиза, кампания, материалы продаж, статьи KB, юридическое одобрение + пост-запускный отчёт.

## 2. Найм нового сотрудника

**Цель:** провести найм от открытия позиции до онбординга.

| Шаг | Скилл | Артефакт |
|---|---|---|
| 1. План найма и источники | human-resources: recruiting-pipeline | План, воронка, источники |
| 2. Подготовка к собеседованиям | human-resources: interview-prep | Вопросы, критерии оценки |
| 3. Анализ компенсации/бюджета | human-resources: comp-analysis | Вилка оффера, бюджет |
| 4. Оффер | human-resources: draft-offer | Оффер-письмо |
| 5. Проверка трудовых обязательств | legal: compliance-check | Одобрение оффера |
| 6. План онбординга | human-resources: onboarding | Онбординг-план |

**Финальный результат:** закрытая вакансия, одобренный оффер, готовый онбординг.

**Цель:** внедрить изменение (процесс, систему, политику) безопасно и с контролем рисков.

| Шаг | Скилл | Артефакт |
|---|---|---|
| 1. Инициация изменения | operations: change-request | Заявка на изменение |
| 2. Оценка рисков | operations: risk-assessment | Карта рисков |
| 3. Техническая реализация | engineering: deploy-checklist | Чек-лист внедрения |
| 4. Проверка комплаенса | legal: compliance-check | Заключение о соответствии |
| 5. Эксплуатация | operations: runbook | Runbook / инструкции |

**Финальный результат:** внедрённое изменение, принятые риски, эксплуатационная документация.

---

## Как проектировать новый процесс

Если шаблона нет, создай процесс по схеме:

1. Определи цель и границы (что входит, что нет).
2. Перечисли роли/домены и их вклад.
3. Для каждого домена выбери скилл из каталога (`orchestrator-catalog`).
4. Выстрой порядок с учётом зависимостей (что чему вход).
5. Определи критичные точки контроля: деньги, клиенты, юридические обязательства — они требуют подтверждения пользователя.
6. Опиши финальный результат и следующий шаг для каждой функции.
