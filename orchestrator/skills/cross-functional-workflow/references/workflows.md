# Сквозные рабочие процессы

Готовые шаблоны для задач, затрагивающих несколько доменов. Каждый процесс: цель → шаги (плагин/скилл → артефакт) → финальный результат. Артефакт каждого шага передаётся как вход следующему.

---

## 1. Запуск продукта (GTM-лейч)

**Цель:** вывести фичу/продукт на рынок согласованно во всех функциях.

| Шаг | Плагин → скилл | Артефакт |
|---|---|---|
| 1. Определить объём продукта | product-management → write-spec | Спека фичи |
| 2. Спланировать релиз | product-management → roadmap-update | План релиза, даты |
| 3. Спланировать кампанию | marketing → campaign-plan | План кампании и каналов |
| 4. Подготовить материалы | marketing → draft-content / content-creation | Посты, письма, лендинг |
| 5. Подготовить продажи | sales → call-prep / draft-outreach | Скрипты звонков, аутрич |
| 6. Юридическая проверка материалов | legal → review-contract / compliance-check | Одобрение, правки |
| 7. Подготовить поддержку | customer-support → kb-article | Статьи базы знаний к релизу |

**Финальный результат:** пакет запуска — спека, план релиза, кампания, материалы продаж, юридическое одобрение, статьи KB.

---

## 2. Найм нового сотрудника

**Цель:** провести найм от открытия позиции до онбординга.

| Шаг | Плагин → скилл | Артефакт |
|---|---|---|
| 1. План найма и источники | human-resources → recruiting-pipeline | План, воронка, источники |
| 2. Подготовка к собеседованиям | human-resources → interview-prep | Вопросы, критерии оценки |
| 3. Анализ компенсации/бюджета | finance → comp-analysis | Вилка оффера, бюджет |
| 4. Оффер | human-resources → draft-offer | Оффер-письмо |
| 5. Проверка трудовых обязательств | legal → compliance-check | Одобрение оффера |
| 6. План онбординга | human-resources → onboarding | Онбординг-план |

**Финальный результат:** закрытая вакансия, одобренный оффер, готовый онбординг.

---

## 3. Закрытие месяца

**Цель:** закрыть финансовый период корректно и в срок.

| Шаг | Плагин → скилл | Артефакт |
|---|---|---|
| 1. План закрытия | finance → close-management | Чек-лист и сроки |
| 2. Журнальные проводки | finance → journal-entry-prep | Проводки |
| 3. Сверка счетов | finance → reconciliation | Сверенные счета |
| 4. Валидация данных | data → validate-data | Проверенные данные |
| 5. Анализ отклонений | finance → variance-analysis | Отчёт по отклонениям |
| 6. Финансовая отчётность | finance → financial-statements | P&L, баланс, cash-flow |

**Финальный результат:** закрытый период, отчётность, пояснения по отклонениям.

## 4. Онбординг нового клиента

**Цель:** провести клиента от подписания до активного использования.

| Шаг | Плагин → скилл | Артефакт |
|---|---|---|
| 1. Подготовка к kickoff-встрече | sales → call-prep | Агенда kickoff |
| 2. Апдейт стейкхолдерам | product-management → stakeholder-update | План внедрения |
| 3. Материалы поддержки | customer-support → kb-article | Статьи/гайды для клиента |
| 4. Документирование процесса обслуживания | operations → process-doc | Runbook обслуживания |

**Финальный результат:** проведённый kickoff, план внедрения, материалы для клиента и команды поддержки.

---

## 5. Внедрение операционного изменения / новой системы

**Цель:** внедрить изменение (процесс, систему, политику) безопасно и с контролем рисков.

| Шаг | Плагин → скилл | Артефакт |
|---|---|---|
| 1. Инициация изменения | operations → change-request | Заявка на изменение |
| 2. Оценка рисков | operations → risk-assessment | Карта рисков |
| 3. Техническая реализация | engineering → deploy-checklist | Чек-лист внедрения |
| 4. Проверка комплаенса | legal → compliance-check | Заключение о соответствии |
| 5. Эксплуатация | operations → runbook | Runbook / инструкции |

**Финальный результат:** внедрённое изменение, принятые риски, эксплуатационная документация.

---

## Как проектировать новый процесс

Если шаблона нет, создай процесс по схеме:

1. Определи цель и границы (что входит, что нет).
2. Перечисли роли/домены и их вклад.
3. Для каждого домена выбери скилл из `references/plugin-catalog.md`.
4. Выстрой порядок с учётом зависимостей (что чему вход).
5. Определи критичные точки контроля: деньги, клиенты, юридические обязательства — они требуют подтверждения пользователя.
6. Опиши финальный результат и следующий шаг для каждой функции.
