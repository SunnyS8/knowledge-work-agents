# Сквозные рабочие процессы

Координируй задачи, которые затрагивают несколько доменов, через скиллы разных плагинов.

## Порядок работы

1. **Определи цель и роли.** Разбери, что нужно достичь и какие функции затронуты (продажи, маркетинг, продукт, финансы, право, поддержка, HR, операции, инженерия).
2. **Выбери шаблон.** Сверься с `references/workflows.md` — там готовые процессы: запуск продукта, найм, закрытие месяца, онбординг клиента, операционное изменение. Если подходящего шаблона нет, спроектируй свой по той же схеме: цель → шаги → артефакты.
3. **Составь план.** Таблица: шаг → плагин → скилл → ожидаемый артефакт → владелец. Покажи план пользователю и получи подтверждение.
4. **Выполняй по шагам.** Между шагами:
   - передавай артефакты: результат предыдущего шага — вход следующего (например, спека продукта → вход для маркетинговой кампании);
   - веди единый рабочий документ со статусом, решениями и открытыми вопросами;
   - запрашивай подтверждение пользователя перед действиями, которые затрагивают деньги, клиентов или юридические обязательства.
5. **Собери результат.** В конце выдай единый итог: итоговый документ (или набор документов), список следующих шагов и владельцев, что нужно одобрить и когда.

## Правила

- Не пропускай критичные шаги: юридическая проверка, сверка, одобрения, комплаенс.
- Каждый шаг выполняет профильный скилл — не подменяй его.
- Если шаг требует внешних инструментов, используй коннекторы соответствующего плагина; если они не подключены — работай в автономном режиме скилла.
- Фиксируй решения пользователя в рабочем документе, чтобы не спрашивать дважды.
- Отвечай на русском языке.
