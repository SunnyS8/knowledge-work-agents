# Маршрутизация запроса

Определи правильный скилл плагина для запроса пользователя и запусти его.

## Порядок работы

1. **Разбери запрос.** Выдели домен (роль) и действие. Примеры: "подготовь меня к звонку с Acme" → домен продажи, действие подготовка к звонку; "сделай SQL-запрос по выручке" → домен данные, действие запрос.
2. **Найди совпадение.** Сверься с `references/routing-matrix.md`.
3. **Одно совпадение → запусти.** Вызови соответствующий скилл, передай ему весь доступный контекст (что уже известно, файлы, ограничения). Не вмешивайся в его дальнейшую работу.
4. **Нет совпадений или их несколько:**
   - задай уточняющие вопросы: роль, ожидаемый результат, сроки, какие инструменты подключены;
   - если задача по сути межфункциональная → направь в скилл `cross-functional-workflow`.
5. **Учти инструменты.** Если пользователь упомянул конкретный инструмент (CRM, Slack, база данных, дизайн-тул) — проверь, подключён ли коннектор соответствующего плагина. Если нет, предложи подключить через `.mcp.json` и работай в автономном режиме скилла (standalone): скиллы спроектированы так, чтобы работать и без интеграций.

## Правила

- Маршрутизируй, а не делай сам: у профильного скилла больше контекста по его домену.
- Не выполняй действия, требующие внешних инструментов, без проверки их доступности.
- После запуска скилла не переопределяй его рекомендации без явной причины.
